EXStar Hub mods (Mod Manager)
=============================

Download the single file ExStarModManager_<version>.exe from Releases:
https://github.com/LeXcite/EXStar_Hub_mod/releases
(one file, no install, x64; the host and every module are inside it, so
there is nothing else to download; it asks for admin rights once, through
the built-in Windows UAC prompt).

The file is not code-signed, so SmartScreen may warn on the first run:
<More info> then <Run anyway>.

The application version shown in the manager is the vendor product number
(e.g. 2.1.0-10) from the uninstall registry key; the file stamp of
EXStar Hub.exe is frozen by the vendor, so the manager shows both.

Mods (each has its own switch)
------------------------------

  Marker Quality   - marker color reflects tracking quality:
                     red = weak, yellow = decent, green = reliable
  Marker In-Frame  - a marker inside the view grows in size instead of
                     flashing red (composes with Marker Quality)
  Popup Dim        - the heavy grey veil behind popups becomes light
                     and translucent, the busy-overlay background
                     becomes frosted glass
  Wallpaper        - your own picture as the application background
  Laser 25+25      - all 25+25 laser lines reach the cloud, the button
                     reads <50 lines> (the stock 7-line mode is kept)
  Zoom to Fit Fill - <Zoom to Fit> (Ctrl+D) frames the model into the
                     whole viewport, not just its center
  GPU Gate         - a computer with an integrated GPU (e.g. Radeon
                     780M) passes the startup GPU check instead of
                     refusing to start the scan software
  Selective Mesh   - close the eye icon of one scan in the project list
                     and that scan is left out of the common mesh
                     (<Mesh Model>); its data stays in the project.
                     The product has no other way to exclude a single
                     scan, so the eye is the whole interface here.

Install
-------
1. Close EXStar Hub.
2. Run ExStarModManager_<version>.exe (admin rights are required -
   normal Windows elevation).
3. Check the green line shows the app folder correctly
   (default C:\Program Files\Shining3d\EXStar Hub, override with
   <Browse>).
4. Flip ON the switches of the modules you want. Done.
5. Start EXStar Hub.

If the window is too big or too small for the screen, restart the
manager with:  ExStarModManager_<version>.exe --zoom 1.5   (1.0 .. 4.0).
The window auto-scales at every start; --zoom forces the factor.

Tunables (per module card, apply after restart)
-----------------------------------------------
- Marker In-Frame: <scale> slider - how much an in-frame marker grows.
- Popup Dim: <dim> slider - how opaque the veil behind popups stays
  (0 = fully transparent).
- Marker Quality: preset row <Coarse / Medium / Fine / Ultra> -
  how precisely markers must be observed to turn green.
- Wallpaper: <Choose file...> - any jpg/png/bmp, converted to a
  1920x1080 JPEG fitted to the vendor slot; <Reset> - back to the
  stock background.
- Selective Mesh: nothing to set. Each scan's switch is the eye icon in
  the project list. Exclusions are kept in
  C:\Users\Public\Shining3d\EXStar Hub\selective-mesh.ini while that run
  of the hub lives, because the mesh is built in another process, and
  every exclusion is dropped when the hub starts - a fresh hub means
  open eyes. If the eyes of a merge are ALL closed, the module ignores
  the exclusions and merges every scan, because the vendor dead-ends an
  empty selection (Processing stops near 80 %).

Uninstall
---------
Press <Restore stock> (or delete by hand): winmm.dll (the proxy),
winmm_real.dll, ExStarRec.dll, modules.ini and the modules\ folder in
the app directory. What the manager placed is recorded in
exstar_mods.state; the *Restore stock* button removes exactly that.
A single module can also be turned off: its switch to OFF + restart.

Command line (same as the GUI, no UI)
-------------------------------------
  ExStarModManager_<version>.exe --list
  ExStarModManager_<version>.exe --install --modules id1,id2 [--app "C:\...\EXStar Hub"]
  ExStarModManager_<version>.exe --remove  --modules id1,id2
  ExStarModManager_<version>.exe --restore
Module ids: marker_quality, marker_inframe, popup_dim, wallpaper,
laser50, fitfill, gpu_gate, selective_mesh.

How to see that a module did something
--------------------------------------
Every module writes one line to
%LOCALAPPDATA%\ExStarHubMods\mod.log when it attaches, for example
"selective_mesh v1.8.0 armed in pid=27920 exe=EXStar Hub.exe". Selective
Mesh also logs each eye it sees toggled ("eye <uuid> -> HIDDEN") and
each merge decision ("gate uuid=... -> include|SKIP"), so a scan that
was left out is explained there.

Nothing here modifies vendor files
----------------------------------
Every change is applied on the next start of EXStar Hub and lives only
in process memory. No project data, no user data is read or copied, and
the log files stay on this computer. Deleting a few files (or the
*Restore stock* button) reverts everything.

One thing to expect: a vendor update replaces the application folder,
and with it our files (winmm.dll, winmm_real.dll, ExStarRec.dll, the
modules folder and the two .ini files). Nothing breaks - the application
just runs as stock until you run ExStarModManager again and flip the
same switches back on. Do it after every update; your tuning is in
modules\<module>.ini, so a copy of that small folder is enough to get
the same settings back.
