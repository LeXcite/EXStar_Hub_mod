# Диапазон плоскостей лазера и подпись режима — протокол RE

Наука за модулем `laser50` (линии + подпись). Статус-журнал:
`batch-2026-11-17-status.md`; qrc-машинерия подписи:
`scanpage-qml-resources.md`.

---

## 1. Симптом и цель

Сканер проецирует 25+25 линий лазера, но в облако доходит 19+19 = 38
(кнопка при этом врёт «39 lines» — номинал модели). Цель: все 50 линий +
честная подпись «50 lines» на кнопке.

## 2. Точка управления: экспорт `set_match_plane_id_vulkan`

Разведка 3.1.x (algorithmLzy.dll 2.1.908.63, sha256 `8c70bd0e…`).
`dumpbin /exports` даёт ровно два релевантных экспорта
(порядки/адреса — значения этой сборки, не константа):

| # | ord | RVA | экспорт |
|---|-----|-----|---------|
| 561 | 0x230 | 0x1A2880 | `?set_match_plane_id_opencl@Sn3DAlgorithm@@YA?AW4RetVal@1@PEAXAEBH111@Z` |
| 562 | 0x231 | 0x1A2890 | `?set_match_plane_id_vulkan@Sn3DAlgorithm@@YA?AW4RetVal@1@PEAXAEBH111@Z` |

Ghidra: тело `set_match_plane_id_vulkan(ctx, &a,&b,&c,&d)` — лог
(`"set_match_plane_id_vulkan satrtId = "`, `"   endId = "`, `"  satrtIdR = "`,
`" endIdR = "` — вендоровые опечатки сохранены) + хвостовой вызов
`FUN_1804b24b0`, которая делает ровно четыре записи:

```c
*(ctx + 0x25534) = a;  *(ctx + 0x25538) = b;
*(ctx + 0x2553c) = c;  *(ctx + 0x25540) = d;
```

То есть окно `(start..end, startR..endR)` задаёт **вызывающий** своими
аргументами-по-ссылке; в конфигах/QML его нет.

## 3. Кто вызывает

Поиск сигнатурой `set_match_plane_id_vulkan` по всем DLL каталога приложения:

```
algorithmLzy.dll: сам экспорт
SnAlgAppPlat.dll: имя импорта (единственный импортёр)
```

Ни один EXE не линкует `SnAlgAppPlat.dll` статически (поиск по EXE — ноль) —
пайплайн грузится динамически. Значит процесс-хост определяется только
рантайм-логом модуля (`armed in pid=` / `hooked`), что и реализовано; модуль
живёт во всех sibling-процессах (`needsSiblings`), а половинка-хук стартует,
когда `algorithmLzy.dll` появляется.

## 4. Три слоя вмешательства (почему выбран экспорт)

1. **Глобалки вызывающего** (путь друга, `STATE.md` приватной базы: правка
   `(3,21,3,21)`→`(0,24,0,24)` в данных импортёра, target `cbcd3f42…`) —
   мертво на первом же обновлении, процесс/модуль-жертва известны только для
   конкретной версии; живьём другом не проверялось.
2. **Контекст алгоритма** `ctx+0x25534` — нужен указатель экземпляра и
   гонка с каждым новым `set_...`.
3. **Экспортируемый сеттер** — именованный ABI-контракт; одна точка; прочие
   вызовы (7-линейный режим) пропускаются строгим сравнением кортежа.
   Выбран. Реализация: `host->hook` (MinHook) на входе экспорта, поиск по
   имени (`ex_findExport`, неоднозначный needle = простои), аргументы читаются
   под SEH, при совпадении `(3,21,3,21)` оригинал вызывается с указателями на
   нашу копию `(0,24,0,24)` — глобалки вендора не пишутся никогда.

Живое подтверждение (2026-11-17): `laser50: hooked ...`,
`call N: (3,21,3,21) -> remap` (×4 за сессию скана), пользователь: «есть
25х25 линий».

## 5. Подпись кнопки: `ScanSettingModelProviderLaser` (ScanPage_E7.dll)

QML-запись (qrc, details: `scanpage-qml-resources.md`), relevant строки:

```qml
// кросс-режим (строка 556 дампа):
text: qsTr("%1线").arg($scanSettingModelLaser.crossLaserLineShowNum)
// параллельный режим (586):
text: qsTr("%1线").arg($scanSettingModelLaser.parallelLaserLineShowNum)
```

- числа (39/7) — свойства C++-модели `crossLaserLineShowNum` /
  `parallelLaserLineShowNum` (номиналы; в дампе DLL имя `crossLaserLineShowNum`
  встречается 2× — meta-object модели, не текст QML: текст лежит упакованным);
- `qsTr("%1线")` — переводимый источник: EN-каталог даёт «%1 lines»
  (скриншот EN UI: «39 lines», «7 lines»).

Правка: только аргумент — `.arg($scanSettingModelLaser.crossLaserLineShowNum)`
→ `.arg(50)` (63 B → 21 B, re-deflate 9587 ≤ 9777). Язык UI сохраняется,
«7 lines» не затронуто. Live: `1 caption(s) rewritten (ok)`, скриншот
«50 lines / 7 lines».

### Несостоявшийся вариант v1.0.0 (расследование утечки «линий»)

Симптом: после патча англоязычный UI показал русское («38 линий» —
пользовательский отчёт). Причины, установленные разборкой:

1. патч менял **ключ перевода** (`qsTr("%1线")` → `qsTr("%1 линий")`) — EN
   каталог перестал попадать, наружу пошёл сырой replacement;
2. число бралось из модели (39), суффикс на него не влиял — цель («50») всё
   равно не достигалась.

Правило зафиксировано в README модуля: переводимый источник не переформулировать.

## 6. Почему линии и подпись — один модуль (v1.1.0)

Подпись без линий обещает 50 при 38; линии без подписи оставляют «39».
Отдельный переключатель = сломанное промежуточное состояние, поэтому
`captions` слит в `laser50` (подвыключатель `captions = 1` остался).
Процессная модель: модуль один, половинки независимы — [lines] живится
`algorithmLzy.dll` (пайплайн-процессы), [caption] — `ScanPage_E7.dll`
(UI-процесс); в чужом процессе половинка просто молчит (caption перестаёт
опрашивать цель через 2 минуты, чтобы скан-воркеры не шумели).
