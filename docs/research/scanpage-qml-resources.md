# Сжатые QML-ресурсы вендора (Qt zrc) — протокол механизма

Общая наука за модулями `popup_dim`, `fps` и `laser50 [caption]`: где живёт QML
страницы сканирования, как он упакован, как правится в памяти процесса до
первой отрисовки и какие ловушки при этом стоят на пути. Статус-журнал партии
фич — `batch-2026-11-17-status.md`; продуктовые детали — README модулей.

---

## 1. Где лежит QML

UI-страницы вендора — НЕ внешние `.qml`-файлы. Они вкомпилированы в Qt
ресурсы (`qrc`) самих DLL (`ScanPage_E7.dll`, `AppUi.dll`,
`pluginSn3DNavigation.dll`, `CompositeComponents.dll`, ...). В образе DLL это
секции только для чтения с последовательностью записей:

```
[u32 BE rawSize][zlib stream][u32 BE rawSize][zlib stream]...
```

- `rawSize` — declaring decompressed size, big-endian;
- поток — обычный zlib (`78` + флаги, `(cmf<<8|flg) % 31 == 0`);
- движок приложения сам распаковывает их своим `zlib1.dll` при старте Qt;
- записи идут подряд, следующий `rawSize` читается сразу за концом предыдущего
  потока — поэтому **граница следующего потока — неприкосновенная константа**.

Признаки для разведки (реализовано в `tools\zrc_lab.exe`, режимы scan/dump):
`cmf==0x78`, контроль FCIV, правдоподобный `rawSize` перед потоком, и после
распаковки — читаемый QML-текст. dump-режим: `zrc_lab.exe <dll> dump <fileoff>
<out>` — выдаёт inflate-нутый текст записи для просмотра/поиска.

## 2. Живые координаты (3.1.x, ScanPage_E7.dll; НЕ константа — только пример)

| запись | file offset | raw | packed (lc) | live VA | VA−file |
|---|---|---|---|---|---|
| страница скана (`/// ScanPage_E7`) | `0x97D318` | 137 735 | 22 753 | `0x97E518` | +0x1200 |
| `ScanSettingModelProviderLaser` | `0x98C90E` | 67 753 | 9 777 | `0x98DB0E` | +0x1200 |

Дельта file↔VA зависит от секций и плывёт с обновлениями — модули оперируют
только содержимым (якорь по тексту), смещения нигде не хардкодятся.
У друга (2.0.0-45) провайдер лазера лежал на `H=0x98C906` — структура
рекордов жива между версиями, содержимое менялось (см. §5).

## 3. Окно внедрения: до DllMain

`LdrRegisterDllNotification` (ntdll) вызывает колбэк в момент отображения
модуля — до его DllMain и до того, как Qt успеет разобрать QML. Правим
запись в отображённом образе (`VirtualProtect` read-write на время записи),
файлы на диске не трогаем; рестарт возвращает вендорское поведение. Worker с
опросом `GetModuleHandleA` — fallback (уведомление не всегда регистрируется,
плюс уже-загруженные случаи).

QML дисковый каталог (`%LOCALAPPDATA%\QML\...`) компилирует байткод по
подписи исходника — обязательный `QML_DISABLE_DISK_CACHE=1` (урок popup_dim,
иначе правка «проглатывается» кэшем на второй-launch).

## 4. Протокол безопасной записи (общий код: `include\exstar_qrc.h`)

1. Inflate записи из образа; гейт по содержимому (`anchor`×N && `pattern`×M),
   не по смещению.
2. Трансформация текста (вставка сниппета или replace-all паттерна).
3. re-deflate **level 9** обязан уместиться в исходную `lc` — иначе пропуск
   (замер «сколько нужно» — только под verbose);
4. байт-точная копия `4+lc` до записи;
5. rawSize(u32 BE) + поток — под одну пару `VirtualProtect`; остаток после
   нового потока обнуляется;
6. контрольный inflate **из образа** и побайтовое сравнение с замыслом;
   несовпадение — восстановить копию, залогировать, остаться вендорским.

Всё чужое чтение/запись под SEH; гонка loader-потока и worker — атомарный
флаг. Форматы строк лога зафиксированы в README модулей (их цитируют
артефакты).

## 5. Переводы: `.qm`-каталоги и как их не ломать

Вендорские QML-строки по- умолчанию китайские (`qsTr("%1线")`), но UI на
английском показывает «lines» — потому что `qsTr` ищет **ключ = текст
источника** в загруженном переводческом каталоге: `.qm`-каталог даёт для EN
`"%1线" → "%1 lines"`. Следствия:

- менять надо НЕ переводимый источник (смена источника меняет ключ —
  каталог промахивается, и сырой replacement утекает во все локали; так
  captions v1.0.0 показал англоязычному пользователю «38 линий»);
- правильно — менять **аргумент форматирования** (`.arg(50)`): ключ цел,
  язык сохраняется, меняется только число;
- если строка реально не переводится (ключа в каталоге нет) — она и в EN
  покажет ханьцзы; проверять надо скриншотом фактического локализованного
  UI, а не дампом QML.

Это же объясняет «другую форму» строк у друга (2.0.0-45: литералы
`qsTr("50线")`) против нашей 3.1.x (`qsTr("%1线").arg(модельное_поле)`):
вендор перевёл подписи на динамические числа из C++-модели между версиями.

## 6. Сухие прогоны (обязательны перед live)

`tools\replace_lab.exe "<dll>" "<anchor>" <from.bin> <to.bin>`:
находит все записи с anchor/pattern, считает вхождения, re-deflate'ит
замысел и печатает `stock=<...> (slack ...) -> patched=<...> FITS|DOES NOT FIT`.
Числа dry-run обязаны совпасть с живым логом байт в байт — так модуль и
харнес используют одну машинерию:

| модуль | from | to | ожидание | живой лог |
|---|---|---|---|---|
| fps | `id: root\r\n` | то же + сниппет 791 B | `@0x97D318 stock=22392 → patched=22610 FITS` (lc 22753) | `raw 137735->138526, packed 22753<-22610 (ok)` |
| laser50 [caption] | `qsTr("%1线").arg($scanSettingModelLaser.crossLaserLineShowNum)` | `qsTr("%1线").arg(50)` | `@0x98C90E pattern=1, stock=9583 → patched=9587 FITS` (lc 9777) | `raw 67753->67711, packed 9777<-9587, 1 caption(s) rewritten (ok)` |

(`fps_lab.c` был отдельным harness'ом вставок — удалён 2026-11-17 после
подтверждения, что replace_lab воспроизводит его числа точь-в-точь.)

## 7. Известные ловушки (все наступили)

- **`#` в значениях ini** резался как комментарий (`color = #8ecbff` → пусто).
  Фикс в хостовом парсере: `#`/`;` вне `"..."`, кавычки съедаются; значения с
  `#` пишем в кавычках.
- **QML disk cache** — см. §3.
- **Граница записи**: правка, раздувшая поток сверх `lc`, сдвинула бы следующую
  запись → белый экран. Поэтому «не влезло = не патчим».
- **Сырой rawSize в ноль** как «отключение записи» — запрещён (Qt пропустил бы
  ресурс целиком → пустая страница); только побайтовый откат.
- **Проверка «уже пропатчено»** по presence-строке сниппета (`exFpsLabel`) или
  наличию replacement — идемпотентность против повторного прохода.
